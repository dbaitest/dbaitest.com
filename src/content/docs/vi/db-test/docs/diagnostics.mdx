"Bộ test chạy chậm" dễ sửa hơn khi có số liệu. db-test có thể ghi một dòng cho mỗi test vào một file phân tách bằng tab.

## Bật lên

<Code code={timingCommand} lang="bash" />

Với `DbTest.MSTest`, lệnh này ghi một dòng cho mỗi test vào `dbtest-timing.tsv` cạnh test binary.

Mặc định tính năng này tắt: không có file nào được ghi trừ khi bạn bật, và chỉ đúng giá trị `1` mới bật nó.

## Chọn file

Đặt `DBTEST_TIMING_FILE` để ghi ra nơi khác:

{/* not in upstream: illustrative */}

```bash
DBTEST_TIMING=1 DBTEST_TIMING_FILE=timings.tsv dotnet test
```

| Biến | Tác dụng |
|---|---|
| `DBTEST_TIMING` | `1` bật tính giờ. Giá trị khác thì giữ nguyên trạng thái tắt. |
| `DBTEST_TIMING_FILE` | Ghi đè đường dẫn output. Mặc định: `dbtest-timing.tsv` cạnh test binary. |

## Nội dung file

File phân tách bằng tab, với header `kind`, `value`, `detail`. Mỗi test là một dòng:

- `kind` là `test`;
- `value` là thời lượng tính bằng mili giây, với một chữ số thập phân;
- `detail` là tên test, `ClassName.TestName`.

File được ghi nối tiếp (append), nên nhiều test assembly có thể dùng chung một file. Header chỉ được ghi khi file mới hoặc còn rỗng.

Chẩn đoán không bao giờ làm fail một lần chạy. Lỗi ghi file được báo trên console rồi bỏ qua.

:::tip
Sắp xếp file theo cột `value` để tìm các test chậm nhất. [CI](/vi/db-test/docs/ci/) có thể upload nó làm artifact.
:::
