Một database project (dự án cơ sở dữ liệu) của SQL Server (SSDT, hoặc `Microsoft.Build.Sql` kiểu SDK) lưu mỗi object trong một file. Các object phụ thuộc lẫn nhau giữa các thư mục, theo cả hai chiều: một table trong `dbo/Tables` có computed column gọi một function trong `dbo/Functions`, và function đó đọc một table khác trong `dbo/Tables`.

Không thứ tự file nào áp dụng được schema như vậy, kể cả `OrderedDirectories`. Project build ra một `.dacpac`, và `DbAiTest.MsSql.Dacpac` deploy nó bằng DacFx, theo đúng thứ tự phụ thuộc.

{/* not in upstream: illustrative */}

```bash
dotnet add package DbAiTest.MsSql.Dacpac
```

:::note
`DacpacSchemaSource` chỉ deploy lên SQL Server. Với bất kỳ engine nào khác, bước setup ném `DbAiTestException` trước khi container khởi động.
:::

## Những điều cần biết

### Thiếu dacpac thì fail trước khi container khởi động

Source kiểm tra cấu hình trước khi container khởi động, nên lỗi hiện ra trong vài mili giây thay vì sau khi pull image và boot server. Thiếu dacpac sẽ ném `DbAiTestException` kèm đường dẫn đầy đủ mà nó đã tìm:

{/* not in upstream: illustrative */}

```text
Dacpac not found at '<full path>'. Build the .sqlproj and copy its .dacpac next to the tests ...
```

Dacpac mà SQL Server từ chối thì khác: setup fail với `SchemaApplyException` nêu tên dacpac và lỗi của server. Mật khẩu đã được loại khỏi thông báo.

### `SchemaSource` và `SchemaRoot` loại trừ lẫn nhau

Một schema source mang theo vị trí và options của riêng nó. Đặt `SchemaSource` cùng với `SchemaRoot` hoặc `SchemaLoadOptions` sẽ ném `InvalidOperationException` khi test đầu tiên khởi tạo, thay vì bỏ qua một trong hai. Chỉ override `SchemaSource`.

Để áp dụng một thư mục qua mô hình source, dùng `DirectorySchemaSource`.

### Deploy options

Khi không truyền options, source deploy với các mặc định sau:

- không xóa gì cả (`DropObjectsNotInSource = false`);
- khả năng mất dữ liệu không chặn deploy (`BlockOnPossibleDataLoss = false`);
- không tạo database mới, vì engine đã tạo rồi (`CreateNewDatabase = false`);
- các thiết lập mức database như recovery model và filegroup bị bỏ qua (`ScriptDatabaseOptions = false`), vì container dùng một lần không cần chúng và chúng là nguyên nhân dễ gây lỗi deploy nhất ở đây;
- mọi command bị giới hạn bởi command timeout của engine (`CommandTimeout` và `LongRunningCommandTimeout`).

Options bạn truyền vào được dùng đúng như đã cho, và một `new DacDeployOptions()` trống hoàn toàn không có timeout. Hãy bắt đầu từ các mặc định:

### Telemetry

DacFx gửi telemetry sử dụng về Microsoft trừ khi biến môi trường `DACFX_TELEMETRY_OPTOUT` là `1`. Đặt `<DacFxTelemetryEnabled>false</DacFxTelemetryEnabled>` trong `.sqlproj` để tắt nó cả lúc build. Repository của chính db-test làm cả hai.
