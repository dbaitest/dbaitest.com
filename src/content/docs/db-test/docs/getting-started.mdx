`DbTest.Core` alone gives the harness without any test framework. `DbTest.MSTest` brings it in.

For the command-line tool, see [the CLI](/db-test/docs/cli/).

## Requirements

- **Docker** must be running. The harness starts real containers through [Testcontainers](https://github.com/testcontainers/testcontainers-dotnet).
- **.NET 8 or newer.** The packages ship a `net8.0` and a `net10.0` asset. .NET 8 and 9 resolve the `net8.0` one, .NET 10 and later the `net10.0` one.

:::note
The CLI rolls forward, so it runs on whichever of those runtimes is installed.
:::

`DbTestRun` is in the `DbTest.MSTest` namespace.

:::caution
Without `[assembly: DoNotParallelize]`, tests that reshape shared objects corrupt each other. A shared container requires a sequential suite.
:::

Without `DisposeAllAsync()`, Testcontainers' resource reaper removes the containers when the test host exits.

## 5. Run it

{/* not in upstream: illustrative */}

```bash
dotnet test
```

The first test of each engine starts its container and applies the schema. Later tests in the run reuse it.

If Docker is not running, the first test fails with the real error and every later test fails fast with the same one, instead of each waiting for its own container to time out.
