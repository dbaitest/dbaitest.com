db-test is a .NET library for **database integration testing**. You write a test body once and run it against **SQL Server, PostgreSQL and MySQL**.

Every run gets a throwaway database container. Nothing touches a shared, staging or production database.

## Why

A database test suite has to solve the same handful of problems, and most teams solve them by hand.

| Problem | What db-test does |
|---|---|
| Where does the test database come from? | A throwaway container per engine, started on first use and shared by the run. |
| How does the schema get there? | Schema files on disk, applied in order, with each engine's own splitting rules. |
| A test dropped a column and the next test failed on it | The [shape guard](/db-test/docs/shape-guard/) fails the test that did it, naming the object and the change. |
| One test's rows leaked into the next | [`CleanAsync()`](/db-test/docs/cleanup/) empties every table whatever the foreign keys, and resets identity counters. |
| "The suite is slow" | [Per-test timings](/db-test/docs/diagnostics/) in a TSV file (`DBAITEST_TIMING=1`). |
| The same assertions written three times | The engine sits behind one abstract class. |

## Packages

| Package | Purpose |
|---|---|
| `DbAiTest.Core` | The engine-agnostic harness, without any test framework. |
| `DbAiTest.MSTest` | `DbAiTestBase` and `DbAiTestRun` for MSTest. Brings `DbAiTest.Core`. |
| `DbAiTest.MsSql` | The SQL Server engine. |
| `DbAiTest.PostgreSql` | The PostgreSQL engine. |
| `DbAiTest.MySql` | The MySQL engine. |
| `DbAiTest.MsSql.Dacpac` | Deploys a SQL Server `.dacpac` as the schema. |
| `DbAiTest.Cli` | The `dbaitest` command-line tool. |
