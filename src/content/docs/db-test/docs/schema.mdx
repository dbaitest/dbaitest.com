## Discovery and order

Files with the extension `.sql` or `.psql` are discovered recursively, whatever the engine.

They are ordered by their relative path, compared case-insensitively. `001_tables.sql` runs before `002_procedures.sql`, so use leading zeros: `10_x.sql` sorts before `2_x.sql`.

:::tip
A file that references an object created by an earlier file must come later. Without ordering rules, a `procedures/` directory runs before `tables/`. Use `OrderedDirectories` below to fix that.
:::

## How each engine applies files

<Tabs syncKey="engine">
  <TabItem label="SQL Server">
    - **Batch separator:** `GO`, a client directive the server rejects. It must be the only token on its line, case-insensitive, optionally indented, with an optional repeat count (`GO 3` sends the batch three times) and an optional `--` comment.
    - **Function body:** `CREATE PROCEDURE`.
    - **Applied as:** one batch per `GO` segment. A batch is sent whole, not split on semicolons, which keeps a `CREATE PROCEDURE` body intact.
  </TabItem>
  <TabItem label="PostgreSQL">
    - **Batch separator:** none.
    - **Function body:** `$$ ... $$`.
    - **Applied as:** the whole file as one command, which keeps every `$$ ... $$` body intact.
  </TabItem>
  <TabItem label="MySQL">
    - **Batch separator:** the `DELIMITER` directive.
    - **Function body:** `BEGIN ... END`.
    - **Applied as:** one statement per delimiter, sent without the delimiter.
  </TabItem>
</Tabs>

The SQL Server and MySQL splitters are real scanners, not line matchers. A `GO` or a delimiter inside a string literal, a quoted identifier or a comment is never a separator, and a column named `delimiter_char` is not a `DELIMITER` directive.

Comments stay in the command they belong to. A trailing piece that holds only comments and whitespace is dropped, because MySQL rejects an empty query.

## Excluding and ordering files

`SchemaLoadOptions` controls discovery. Override `SchemaLoadOptions` in a `DbAiTestBase` class, or pass it to the harness.

| Option | Effect |
|---|---|
| `ExcludedDirectories` | Directory names whose files are skipped entirely. Matched case-insensitively against each directory segment of the relative path. |
| `ExcludedFileNamePatterns` | Regular expressions matched against the file name, case-insensitively. A match excludes the file. A pattern that takes longer than one second throws. |
| `OrderedDirectories` | Directories, relative to the schema root, applied in exactly this order before any other file. A directory includes its subdirectories. |

## When a script fails

A schema that only partly applied would surface later as unrelated test failures. db-test fails loudly at setup instead.

A failing file does not stop the apply: every file is tried, and `StartAsync` throws a `SchemaApplyException` listing every broken file with the error the engine raised. The exception's `Failures` property holds each one as a `SchemaApplyFailure` with `RelativePath` and `Error`.
